# vb-chat（VBチャット・仮）

**登録なしでも参加できるリアルタイムのチャット**と、アカウントを作った人が書ける**ブログ**のサイトです。
VB.NET（ASP.NET Web Forms）で作りました。

- 本番：https://vb-chat.rana-grande.biz（検索エンジンには載せていない＝noindex）
- 使い方：[画面の写真つきで7ページ](https://vb-chat.rana-grande.biz/articles/kanrinin/howto)
- 技術：VB.NET / ASP.NET Web Forms（.NET Framework 4.8）／SignalR 2.4.3／SQL Server／JavaScript（jQuery）と CSS
- 作った人：森真樹（個人開発）

> このリポジトリは、見ていただくために、サイトを動かすのに要る部分だけを取り出したものです（開発の履歴は含めていません）。
> コードの中の住所・メールアドレスは例の値（`example.com`）にしてあります。

---

## なぜ作ったか

2000年代初頭にある会社で社内SE的な立場になり、独学で Access と SQL Server で業務システムを作り、その後 VB.NET（ASP.NET Web Forms）でCMSを自作しました。その頃、リアルタイムチャットのサイトをよく利用していたので、SignalR が出た時に自作にチャレンジ。ただ、作り切れずに中断していたところ、最近になって AI を使うようになり、もう一度挑戦したくなったことが理由です。

## サイトの詳細

| | |
|---|---|
| **チャット** | 登録なし。名前・アイコン・色を決めるだけで入れる。パソコンでもスマホでも、ブラウザだけで使える |
| **ラウンジ** | 部屋の一覧と、ラウンジにいる人。誰がどの部屋に入った・出たかが、リアルタイムに反映する |
| **部屋** | 固定の部屋のほかに、自分で部屋を作れる（定員・パスワード・満員のときのノック・画像を送れるかを設定）。作った人は管理人として、管理人をゆずる・退室させる・入室禁止にする、ができる |
| **部屋の中** | 発言・絵文字・スタンプ・画像／1人とだけ話せる「こっそり話す」／苦手な相手の発言を自分の画面からだけ消せる「非表示」／合言葉から作る10桁の印で、アカウントが無くても本人だと示せる「トリップ」／部屋に居たまま、自分の色とアイコンを変えられる（管理人は部屋の設定も）／入退室と発言の通知音（オン・オフはどの画面で切り替えても全部に効く） |
| **アカウント** | メールで確かめる登録・パスワードの再設定・退会／チャットで名前の横に「@アカウントID」を出せる（出さないこともできる）／自分が入った部屋のログを、あとから読み返せる |
| **ブログ** | アカウントユーザーが利用できる。見たままの形で書ける記事の画面（自動保存・目次・画像）・カテゴリ・ゴミ箱・プロフィール |
| **運営** | 問い合わせ・お知らせ／エラーが起きたらメールで知らせる／前日の利用の数をメールで知らせる／古いログと画像を自動で片付ける |
| **ログを調べる** | 管理人だけ。検索（期間・部屋・名前・トリップ・IP・アカウントID・種類）／その時間の部屋の様子を再生（在室者・こっそりも表示）／IP・ポート番号・ミリ秒までの時刻／CSV 書き出し／閲覧の記録 |
| **軽さ** | ラウンジは変化のあった1件ぶんだけを配る／画像は送る前にブラウザで縮める／アイコンは1枚の SVG にまとめる／CSS・JS・画像はブラウザに30日覚えさせ、直したときだけ取り直させる |

## フォルダの並び

機能ごとにフォルダを分けています（Feature Folders）。

| フォルダ | 中身 |
|---|---|
| `Chat/` | チャット（部屋・ラウンジ・SignalR のハブ `Chat/Hubs/`） |
| `Accounts/` | アカウント（ログイン・登録・設定・プロフィール）と管理画面の外枠 |
| `Articles/` | ブログ（記事・カテゴリ・記事の画像・HTML のサニタイズ） |
| `Contacts/`・`Notices/` | 問い合わせ・お知らせ |
| `Core/` | 複数の機能で使う共通部分（設定・メール・エラー報告・日次の処理・URL の正規化 など） |
| `Admin/` | ログを調べる道具・保守用の画面（アイコン画像の生成・メール送信の試験・記事の画像の台帳の作り直し） |
| `Scripts/`・`Content/` | JS と CSS（外部ライブラリは `lib/` の下） |
| `Database/` | テーブル作成・初期データの SQL |

## 設計で工夫したところ

- **ログイン無しの身元**：名前の札（署名した Cookie）で「同じブラウザの同じ人」を見分ける。アカウントのログインも、サーバーに「誰がログイン中か」を持たない署名の Cookie で、パスワードを変えると鍵の世代が進んで古い Cookie が全部無効になる（`Database/CreateTable/Accounts.sql` の TokenGeneration）
- **人との距離を取る道具**：「非表示」は相手の発言を自分の画面からだけ消す。無視している相手には「こっそり」も送れない。入室禁止は部屋ごとに続けて効く
- **守りは入口と出口の両方**：記事の HTML は保存のときと出すときの両方でサニタイズ。二重送信の防ぎ（`Core/FormOnce.vb`）、レート制限、エラーは握りつぶさずメールで知らせる（`Core/ErrorReport.vb`）
- **設定にすると弱められる値は、設定にしない**：パスワードの長さの下限などはコードに置き、管理画面からは変えられない（`Accounts/AccountPassword.vb`）
- **何度流しても安全な SQL**：`Database/` の SQL はどれも「無いときだけ作る・入れる」形

## 作り方：私とAIの3人のチーム

| 役 | だれ | すること |
|---|---|---|
| 決める・確かめる | **私** | 要件定義（何を作るか・どの順に作るか）。出来たものを自分の目で確かめて、合格を出す |
| 設計と進行 | **設計役の AI**（Claude のデスクトップアプリ。作業フォルダを接続したチャット） | 私と相談して形を決め、実装担当への作業の指示を書く。|
| コードを書く | **実装役の AI**（Claude Code） | コードを書き、道具で確かめ、本番へ出し、結果を報告する |

私と設計担当は、普通のチャットで相談します。設計担当と実装担当のやり取りはファイルです（指示＝`obj/prompt-to-code.md`、報告＝`obj/report-to-chat.md`）。私は、2人の間をつなぎます。

## AI と作るための運用ルール詳細

### 1. AI が読むファイルを肥大化させない

AI が指示通りに動き、かつトークンの消費を抑えるために、以下の様な決まりにしました。

| 置き場所 | 中身 | いつ読まれるか |
|---|---|---|
| `CLAUDE.md` | 毎回守る決まり・次にやること・目次 | 毎回 |
| `.claude/rules/` | ある種類のファイルを触るときだけの決まり | そのファイルを触ったとき |
| `.claude/skills/` | 機能ごとの説明書 | その機能を触るとき |
| `docs/` | AI との進め方（ai-development） | 必要なときだけ |

これらのファイルは、このリポジトリには入れていません。

毎日の作業の最後に md ファイルの整理を行います。

### 2. 指摘したことを、次からの基本ルールにする

画面の確認、設計の相談、AI の案への判断、文章の直しなど、私が指摘したことは、AI が「次からも使えるか」を考えて案を出し、私が判断して基本ルールに加えました。最初からその基本ルールで作らせて、同じ直しを繰り返さないためです。
AI の報告にも、うまくいかなかったこと・やらなかったことを必ず書かせて、同じように基本ルールへ反映しています。

### 3. 手順の抜け漏れを、道具で防ぐ

セットでやる作業は、人や AI が覚えておく形にせず、道具に組み込みました。

- **本番の DB へ SQL を流す道具**：コミット済みのファイルしか流せない。その日のバックアップが無いと止まる。既定はドライランで、`-Run` を付けたときだけ実行する。削除を含む SQL は、さらに `-AllowDelete` が無いと流れない。流したあとは、サーバーのキャッシュを捨てさせる（`Tools/prod-sql.ps1`）
- **発行の道具**：発行漏れを防ぐため、送るファイルをハッシュ値で決め、送ったあとに本番の応答と突き合わせる（`Tools/deploy.ps1`・`Tools/probe-deploy.ps1`）
- **画面の写真の道具**：直す前と後を撮って比べる（ビジュアルリグレッションテスト）（`Tools/shots.ps1`）
- **バックアップの道具**：開発機の DB・フォルダ・Git を外付けへ。本番の DB とファイルも控える（`Tools/backup-daily.ps1`・`Tools/backup-prod.ps1`）

これらの道具は、このリポジトリには入れていません。

### 4. 使っている道具と部品を、最新に保つ

AI は毎日最初の作業で、Claude Code と使っている部品（NuGet・npm）に新しい版や脆弱性の知らせが出ていないかを確かめて、あれば報告します。

### 5. 最後の判断は人がする

- 本番のデータを消す SQL は、AI がドライランまで行い、本番での実行は私が行います
- 発行のあとは、道具が本番との突き合わせを行い、最後に私が PC とスマホで確認して合格を出します
